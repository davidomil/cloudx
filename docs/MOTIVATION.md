# Why CloudX

Production development involves more than an agent prompt: a project
directory, implementation, tests, diffs, source documents and review
feedback all need attention. CloudX keeps those activities in one
desktop workspace.

## Continuity of work

A window holds the context for a project. Split panes keep an agent
terminal beside files, checks and a local preview. Named windows let you
return to another task, and layout templates reproduce a useful
arrangement for another project.

Worktrees separate parallel branches. Documentation preserves reference
material for later search. Rules & Skills makes repeated instructions
reusable. Jira, Forge Workers and Automation connect issue work with
execution and review.

## A developer-controlled environment

CloudX runs on the machine that holds your repositories and tools. That
gives the workspace real host capabilities and makes the deployment
boundary part of the product: local access by default, private
authenticated access when remote, and explicit allowed roots.

Desktop work is the primary experience. Mobile access provides another
way to check the same workspace; voice and typed AI controls offer
optional ways to steer it. Neither is required to browse files, use
terminals or review work.

Start with the [demo workspaces](DEMO_WORKSPACES.md), then choose tools
from the [plugin catalog](plugins/README.md).
